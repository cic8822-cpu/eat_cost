# 교직원 급식비 신청·징수 자동화 시스템

Google Sheets + Google Apps Script(HTMLService)로 만든 교직원 급식비 신청/집계/징수 자동화 웹앱입니다.
직원이 웹 화면에서 본인의 급식 가능일을 체크해 제출하면, 시트에 자동 반영되고 급식비가 계산되며 안내 메일이 자동 발송됩니다.

## 배포 주소

- 운영 중인 구글 시트(웹앱 바인딩 원본): https://docs.google.com/spreadsheets/d/1CBCOGmF7Dm8HH3YeOc8BFv46ZEsRgLy-R0XG-SJoXwc/edit?gid=1416788502#gid=1416788502
- 다른 학교에서 사용하려면 이 시트를 "파일 → 사본 만들기"로 복사한 뒤 아래 "다른 학교로 배포하기" 절차를 따릅니다.

## 시트 구조 (요약)

- **데이터**: 직원 마스터. A순/B직급/C성명/D이메일/E직원ID/F재직여부(Y/N)
- **학교급식**: 월별 신청 원장. B1=년도, D1=월, F1=급식단가. 2행 헤더(순/직급/직원명/이메일/총일수/급식단가/급식비), H2:AL2=1~31일, AM=제출일시/AN=비고/AO=메일상태/AP=직원ID(매칭 키)
- **개인별내역**: 징수내역 출력용. 스크립트가 학교급식 기준으로 전체 재생성
- **설정** *(Setup.gs가 자동 생성)*: A:B=운영 설정(KEY/VALUE, 학교명·은행명·입금기한·담당자메일·메일제목), D:F=날짜별 급식가능일(가능/불가/주의/사유)
- **제출로그** *(Setup.gs가 자동 생성)*: 제출 이력 append-only 감사 로그

## 설치·운영 절차 (이 학교 / 이미 만들어진 시트 기준)

1. **초기 설정(최초 1회, 수동)**: 스크립트 편집기(`gas` 프로젝트)에서 `Setup.gs`의 `runInitialSetup` 함수를 직접 실행하고 권한을 승인합니다. 데이터 시트 열 추가, 설정/제출로그 시트 생성, 직원ID 부여, 학교급식 동기화, 관리자 토큰 발급, 구조 점검까지 한 번에 처리됩니다.
   - *왜 수동인가*: `clasp run`으로 원격 실행하려면 스프레드시트/메일 발송 권한을 포함한 OAuth 동의가 필요한데, clasp 자체 OAuth 앱은 Google 정책상 이 조합의 민감한 범위를 요청할 수 없어(미검증 앱 차단) 자동화가 불가능합니다.
2. **스크립트 속성 입력**: 프로젝트 설정 → 스크립트 속성에 `BANK_ACCOUNT`(계좌번호), `ACCOUNT_HOLDER`(예금주)를 입력합니다. 코드에 하드코딩하지 않습니다.
3. **설정 시트 값 입력**: `SCHOOL_NAME`, `BANK_NAME`, `PAYMENT_DEADLINE`, `ADMIN_EMAIL` 등을 채웁니다.
4. **배포**: 확장 프로그램 → Apps Script → 배포 → 새 배포 → 웹 앱(실행 계정: 나, 액세스: 모든 사용자)으로 URL을 발급합니다. 메뉴 "급식비 관리 → 🚀 웹앱 배포(자동)"도 있지만, 사본의 기본 GCP 프로젝트가 사용자 접근이 불가능한 경우(대부분의 일반 사본이 여기 해당) `Apps Script API has not been used in project ...` 오류로 실패합니다 — 이 경우 위 수동 방법을 사용하세요. 관리자 상세표는 `URL?admin=<토큰>`으로만 접근합니다(토큰은 초기 설정 시 발급되며, 메뉴 "관리자 토큰 재발급"으로 갱신 가능).
5. **월 전환**: 시트 B1/D1을 직접 수정하지 말고 메뉴 "급식비 관리 → 월 마감"을 사용합니다(현재 월 데이터를 아카이브 후 다음 달로 전환).
6. **테스트/재사용 시 자료 정리**: 메뉴 "급식비 관리 → 제출자료 초기화"로 모든 직원의 급식일 체크·제출일시·비고·메일상태를 한 번에 삭제할 수 있습니다(직원 목록/직원ID는 유지).

## 다른 학교로 배포하기 (템플릿 복사 + 설정 마법사)

exe 설치 프로그램 방식은 만들지 않았습니다 — Google이 시트/메일 접근 권한을 앱 종류와 무관하게 사람이 브라우저에서 최소 1회 직접 승인하도록 강제하기 때문에, exe로 감싸도 이 인증 단계를 대신할 수 없습니다. 대신 **구글시트 템플릿 복사 + 1회 설정 마법사**로 사실상 같은 수준의 간편함을 구현했습니다.

**다른 학교 담당자가 할 일 (약 2분)**

1. 이 스프레드시트를 열고 **파일 → 사본 만들기**를 클릭합니다. (바인딩된 Apps Script 코드도 함께 복사됩니다.)
2. 사본을 열면 메뉴에 **"급식비 관리" → "🎉 처음 시작하기(설정 마법사)"** 가 보입니다. 클릭합니다.
3. 최초 실행이라 Google 권한 승인 창이 뜹니다 → 계정 선택 → 고급 → 이동 → 허용. (자신이 소유한 사본이라 뜨는 정상적인 1회성 절차입니다.)
4. 다시 메뉴에서 마법사를 열고, 학교명 · 은행명 · 계좌번호 · 예금주 · 입금기한 · 담당자 이메일 · 대상 년/월 · 급식단가를 입력한 뒤 **"설정 시작"** 클릭.
5. `데이터` 시트에 직원 명단을 입력합니다(직원 동기화는 웹 접속 시 자동으로 이뤄짐).
6. 확장 프로그램 → Apps Script → 배포 → 새 배포 → 웹 앱(실행 계정: 나, 액세스: 모든 사용자)으로 URL을 발급하고 직원들에게 공유합니다.
   - 마법사 완료 화면의 "자동 배포 시도해보기" 버튼도 있지만, 대부분의 사본에서는 Google의 기본 GCP 프로젝트 접근 제한으로 실패합니다(고칠 수 없는 구조적 제약). 안 되면 바로 위 수동 방법을 사용하세요.

`SetupWizard.html`(폼) + `Setup.gs`의 `runGuidedSetup()`(구조/설정)이 이 흐름을 처리합니다. `DeployService.gs`의 `deployNow()`(자동 배포)는 원본처럼 이미 Apps Script API가 정상 동작하는 프로젝트에서만 작동하는 보조 기능입니다.

| 메뉴 | 기능 |

| 직원ID 부여 | 데이터 시트에 EMP001... 형식 ID 자동 부여 |

| 월 마감(다음 달로 전환) | 현재 월 데이터 아카이브 후 다음 달로 전환 |
| 제출자료 초기화 | 급식일 체크·제출일시·비고·메일상태 일괄 삭제 |
| 개인별내역 재생성 | 개인별내역 시트 강제 재생성 |
| 테스트 메일(본인) | 본인 계정으로 안내 메일 발송 테스트 |
| 관리자 토큰 재발급 | 관리자 상세표 접근 토큰 재발급 |
| 🚀 웹앱 배포(자동) | Apps Script API를 자가 호출해 새 버전 생성 및 웹앱 배포/재배포를 자동 처리 (보조 기능, 사본의 기본 GCP 프로젝트가 접근 제한된 경우 실패 — 이때는 수동 배포 사용) |

## 현재 상태 / 알려진 제약

- 웹앱 접근 범위는 기본값 "모든 사용자"(로그인 불필요, `ANYONE_ANONYMOUS`)로 설정되어 있습니다. 학교 구글 계정 로그인 기반으로 바꾸려면 `appsscript.json`의 `webapp.access`와 배포 설정을 변경해야 합니다.
- 실시간 제출현황은 20초 주기 폴링 + 탭 재활성화 시 갱신으로 구현되어 있습니다(완전한 실시간 푸시는 아님).
- 관리자 상세표는 토큰 기반 접근이며, 일반 직원 화면에는 집계 카운트만 노출됩니다(개인정보 보호).
- 자동 배포 기능은 스크립트가 자기 자신을 배포할 수 있도록 `script.deployments`/`script.projects` 권한을 추가로 요청합니다(권한 승인 창에 항목이 더 많아짐). 원치 않으면 메뉴의 "🚀 웹앱 배포(자동)" 대신 수동으로 "배포 → 새 배포 → 웹 앱"을 사용해도 됩니다.
