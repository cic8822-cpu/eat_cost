# 교직원 급식비 신청·징수 시스템 (로컬 서버판)

## What This Is

학교 교직원이 웹 화면에서 본인을 선택하고 해당 월의 급식 가능일을 체크해 제출하면, 급식일수·급식비가 자동 계산되고 관리자가 대시보드에서 전체 제출현황을 확인·엑셀로 내보낼 수 있는 시스템이다. 기존에는 구글시트+Apps Script(OAuth 기반)로 만들었으나 다른 학교에 배포할 때 Google OAuth 권한/GCP 프로젝트 제약으로 재배포가 어려웠다. 이 시스템은 exe 더블클릭으로 학내망(고정IP) 전용 로컬 파이썬 웹서버를 띄우는 방식으로 이 제약을 근본적으로 없앤다.

## Core Value

교직원이 링크만으로 간단히 급식 신청을 제출하고, 담당자가 이를 취합해 개인별/전체 급식비를 정확히 산출할 수 있어야 한다 — 이것이 안 되면 나머지는 의미가 없다.

### Active

- [ ] exe 더블클릭 시 로컬 웹서버가 실행되고, 학내망 IP:포트 접속 주소가 화면(콘솔/트레이 등)에 표시된다
- [ ] 최초 실행 시 설정 마법사로 학교명·은행명·계좌번호·예금주·입금기한·급식단가·대상 년/월을 입력해, 다른 학교도 동일 exe를 재사용할 수 있다
- [ ] 직원 화면은 기존 gas/Index.html·CSS.html·JavaScript.html과 동일한 레이아웃·문구·검증 로직으로 "본인 선택 → 급식 가능일 체크(전체체크/해제, 불가일 비활성화, 비고 입력) → 제출" 흐름을 제공한다
- [ ] 제출 완료 시 이메일 대신 화면에 "급식비 얼마를 언제까지 어느 계좌로 입금" 안내가 표시된다
- [ ] 실시간 제출현황(전체 인원 중 제출 인원)이 기존과 동일하게 주기적 자동 폴링으로 갱신된다
- [ ] 데이터는 로컬 파일(SQLite)에 저장되어 서버를 종료해도 유지된다
- [ ] 관리자는 별도 로그인 없이(학내망 폐쇄망 가정) 대시보드에서 직원별 제출현황(급식일수·급식단가·급식비·제출상태·비고)을 확인할 수 있다
- [ ] 관리자는 대시보드에서 직원(교직원) 명단을 추가/삭제할 수 있다
- [ ] 관리자는 엑셀 업로드로도 직원 명단을 등록/갱신할 수 있다
- [ ] 관리자는 현재 데이터를 기존 구글시트와 거의 동일한 시트 구조(학교급식/개인별내역)의 엑셀로 내보낼 수 있다
- [ ] "작업 종료" 동작 시 엑셀로 저장한 뒤 서버의 제출 데이터를 삭제(휘발)한다
- [ ] 다음 달에는 내보냈던 엑셀을 다시 업로드해 직원 명단 등을 이어서 사용할 수 있다
- [ ] Windows 방화벽/스마트스크린 경고가 뜰 수 있음을 사용자에게 안내하는 문구/화면이 포함된다

### Out of Scope

- 이메일 자동 발송 — 화면 안내 문구로 대체 (요청에 따라 불필요)
- Google OAuth/GCP 기반 배포 — 학내망 고정IP 로컬 서버 방식으로 전환하며 폐기
- 관리자 화면 로그인/토큰 인증 — 학내망 폐쇄망이라는 전제하에 생략 (필요 시 추후 재검토)
- 외부 인터넷 접속/클라우드 동기화 — 학내망 전용, 인터넷 노출 없음

## Context

- 기존 구현: `gas/` 폴더(Code.gs, Config.gs, EmployeeService.gs, MealService.gs, BillingService.gs, EmailService.gs, AdminService.gs, Setup.gs, DeployService.gs, Index.html, CSS.html, JavaScript.html, SetupWizard.html, appsscript.json) — 구글시트 3개 탭(데이터/학교급식/개인별내역) + 설정/제출로그 탭 구조로 동작 중.
- 기존 시트 구조 요약(README.md 기준):
  - **데이터**: 직원 마스터 — 순/직급/성명/이메일/직원ID/재직여부(Y/N)
  - **학교급식**: 월별 신청 원장 — B1=년도, D1=월, F1=급식단가, 2행 헤더(순/직급/직원명/이메일/총일수/급식단가/급식비), H2:AL2=1~31일, AM=제출일시/AN=비고/AO=메일상태/AP=직원ID
  - **개인별내역**: 징수내역 출력용, 학교급식 시트 기준 재생성
- 기존 UX(JavaScript.html 기준): 직원 선택 → 급식 가능일 그리드(불가일 비활성화, 주의일 별도 표시) → 전체체크/해제 → 선택일수×급식단가=급식비 실시간 표시 → 비고 입력 → 제출 → 실시간 제출현황 20초 폴링 갱신 → 관리자 상세표(토큰 접근 시).
- 배포 시도 중 확인된 제약: `clasp run` 원격 실행 시 OAuth 미검증 앱 차단, 사본의 기본 GCP 프로젝트 접근 제한으로 자동 배포(`deployNow`) 실패 — 이 두 제약이 이번 로컬 서버 전환의 직접적인 동기.
- 참고 자료: `README.md`, `0.작업지시-1.txt`(최초 요구사항), `구글시트 구글앱스크립트 프로그램/2.claude-계획1.txt`(구현 계획서, 함수 명세, 테스트 체크리스트 T1~T30), `html 화면-1.png`(초기 UI 목업).

## Constraints

- **배포 환경**: 학내망(고정IP) 전용 — 인터넷 노출 없이 동작해야 함
- **패키징**: 최종 산출물은 exe 단일 실행 파일(더블클릭 실행) — 별도 파이썬 설치 없이 동작해야 함
- **UX 호환성**: 직원용 화면은 기존 gas 버전과 동일한 레이아웃·문구·검증 로직을 재사용해야 함 (사용자 재학습 비용 최소화)
- **개발 절차**: bypass-permission 미사용, 정상 승인 절차 유지 — phase별 작업 → code-reviewer 에이전트 검증 → lint/오류 수정 → 문서 업데이트 순으로 진행
- **문서화**: 계획.md/prd.md/task.md/로드맵.md/test.md/체크리스트.md/로그.md 형태의 산출물을 프로젝트 진행 중 작성

## Evolution

이 문서는 phase 전환과 마일스톤 경계에서 갱신된다.

**각 phase 전환 후** (`/gsd-transition` 통해):
1. 요구사항이 무효화됨? → 이유와 함께 Out of Scope로 이동
2. 요구사항이 검증됨? → phase 참조와 함께 Validated로 이동
3. 새 요구사항이 발견됨? → Active에 추가
4. 기록할 결정이 있음? → Key Decisions에 추가
5. "What This Is"가 여전히 정확한가? → 어긋났다면 갱신

**각 마일스톤 후** (`/gsd-complete-milestone` 통해):
1. 전체 섹션 재검토
2. Core Value 재확인 — 여전히 맞는 우선순위인가?
3. Out of Scope 재검토 — 이유가 여전히 유효한가?
4. Context를 현재 상태로 갱신
