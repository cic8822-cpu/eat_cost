## 0. 요약(Executive Summary)

- **목표**: 교직원이 Web App에서 본인을 선택하고 해당 월의 급식 가능일을 체크·저장하면, 시트에 날짜별 `1`이 기록되고 급식일수·급식비·개인별 징수내역·담당자 집계가 자동 갱신되며 안내 이메일이 발송되는 구조를 만듭니다.
- **코드리뷰 핵심 발견 4가지**: ① **제출상태(제출완료/미제출)의 데이터 소스가 사양에 없음** ② **담당자 집계표가 전 직원에게 노출되는 개인정보 문제** ③ **`순`(=ROW()-1)을 직원키로 쓰면 행 삭제 시 데이터가 밀림** ④ **H2:AL2 날짜 헤더의 소유권(수식 vs 스크립트) 충돌**. 이 4가지를 포함해 **P0 6건, P1 9건**을 본 계획에 반영했습니다.
- **핵심 설계 결정**: 직원ID(`EMP001`) 도입, 학교급식 시트에 `제출일시/비고/메일상태` 3개 열 추가, `설정` 시트에 급식가능일 표(가능/불가/주의), E·F·G열은 수식 유지 + 나머지는 스크립트가 값으로 기록하는 **하이브리드**, `MailApp` 사용, `ScriptLock` 적용, 관리자 상세표는 토큰 또는 시트 대시보드로 제한, "월 마감" 메뉴로 아카이브 후 월 전환.
- **코딩 전 사용자 확인 필요**: 5건(3장). 답변이 없으면 각 항목의 **권장 기본값**으로 진행합니다.

## 1. 코드리뷰 결과 요약 및 반영 내역

### 1.1 기존 워크북 점검(사양서 §17 체크리스트 11개 항목)

| §17 | 항목 | 판정 | 근거(셀) | 본 계획의 반영 |
|---|---|---|---|---|
| 1 | 년도/월 셀 위치 | 양호 | 학교급식!B1=2026, D1=9, F1=6500 | 유지. 단 **운영 전 D1=10, F1=6850 갱신** 절차를 11장에 포함 |
| 2 | 일자 셀 서식 | 잠재 위험 | H2:AL2는 수식 결과 숫자(1~31) | 헤더는 스크립트가 **숫자 값**으로 생성, 컬럼 매핑은 `day+7`로 고정 |
| 3 | `#NAME?` 수식 | 없음 | 캐시값 전수 확인 | 이관 후 `EOMONTH` 재확인만 |
| 4 | 총일수 범위 31열 | 일치 | E3=`SUM(H3:AL3)` | `DAY_COL_START=8, DAY_COL_COUNT=31` 상수 |
| 5 | 직원 추가/삭제 시 고정 행 참조 | **치명** | 학교급식!A3:D16=`데이터!A2:D15` 행별 고정 참조 → 삭제 시 `#REF!`, 추가 시 미반영 | **직원ID 기준 스크립트 동기화**로 교체(P0-6) |
| 6 | 개인별내역 자동 대응 | **치명** | A4:C17 **하드코딩 명단**, D:F 고정 행 참조, 합계 범위 고정, E24 잔존 셀 `급` | **스크립트가 4행부터 전체 재생성**(P0-6) |
| 7 | 이메일 없는 직원 | 운영 문제 | 14명 중 **13명 이메일 공백**, 헤더 `'이메일 '`(끝 공백) | `trim()` + 형식검증 + `NO_EMAIL` 로그, 자기진단 함수 |
| 8 | 년/월 변경 시 유실 | **치명** | D1 변경 시 헤더만 바뀌고 H3:N16 `1`값 잔존 | **월 마감(아카이브) 메뉴**(P0-5) |
| 9 | 동명이인 | 구조 취약 | 키 없음, 영문명 공백 포함 | 직원ID 도입, 표시명 `직급 · 성명 (순)` |
| 10 | 중복 제출 | 구조 미비 | 제출상태·시각 없음 | `제출일시` 열 추가, H:AL 31칸 **전체 덮어쓰기** |
| 11 | 동시 저장 충돌 | 구조 미비 | 스크립트 없음 | `LockService.getScriptLock()` 30초 |

- 추가 발견: 학교급식!F3:F16=`$F$1`이므로 **단가 변경이 과거 월에 소급**됨 → 월 마감 아카이브로 이력 보존.

## 2. 확정 요구사항 및 기본값(Decisions)

아래 항목은 **질문 없이 기본값으로 확정**하여 진행합니다. 변경을 원하시면 코딩 전에 알려 주십시오.

| 영역 | 결정 | 이유 |
|---|---|---|
| 직원 식별키 | 데이터!E열 `직원ID`, 형식 `EMP001`, 관리자 메뉴가 빈 셀에만 자동 부여, 수동 변경 금지 | 행 삭제·정렬·동명이인에 안전 |
| 표시용 `순` | 데이터!A열 `=ROW()-1` 유지, 정렬·표시 전용 | 기존 업무 화면과 동일 |
| 날짜 헤더 H2:AL2 | 스크립트가 숫자 값(1~말일, 나머지 빈칸)으로 생성, 수식 삭제 | 컬럼 매핑을 스크립트가 단독 소유 |
| E/F/G열 | **수식 유지**(`=SUM(H:AL)`, `=$F$1`, `=E*F`), 서버는 응답·메일용 금액을 **자체 계산** | 시트 직접 수정 시에도 일치 보장 + flush 전 stale 값 회피 |
| 제출상태 | 학교급식!AM `제출일시`(문자열 `yyyy-MM-dd HH:mm:ss`, Asia/Seoul), AN `비고`, AO `메일상태` | 0일 제출과 미제출 구분 |
| 급식가능일 | `설정` 시트 표 `dateKey / 상태(가능·불가·주의) / 사유`, 월 생성 시 토·일 자동 `불가`, 담당자가 공휴일·예외 편집 | 확장성(§6) + 목업의 예외일 표시 |
| 예외일(`주의`) 기본 동작 | 선택 가능하되 **기본 해제 + 경고 문구** (3장 Q4로 확인) | 목업 `10/21(수)*` 해석 |
| dateKey | 서버·클라이언트 모두 `YYYY-MM-DD` 문자열만 교환, 표시 라벨(`10/1(목)`)은 서버가 생성 | 타임존 하루 밀림 방지 |
| 잠금 | `LockService.getScriptLock()`, `waitLock(30000)`, 메일은 **잠금 해제 후** 발송 | 동시 제출 안전 + 잠금 점유 최소화 |
| 오류 응답 규약 | 서버는 `throw` 대신 `{ok, code, message, data}` 반환, 클라이언트는 모든 호출에 `withFailureHandler` | 사용자 친화적 오류 표시 |
| 메일 | `MailApp.sendEmail`(텍스트 본문), 발송 전 `getRemainingDailyQuota()` 확인, 발신자=배포 계정 | 최소 스코프, 학교 Workspace 제한 대응 |
| 설정값 분리 | Script Properties: `BANK_ACCOUNT`, `ACCOUNT_HOLDER`, `ADMIN_TOKEN` / 설정 시트: `SCHOOL_NAME`, `BANK_NAME`, `PAYMENT_DEADLINE`, `ADMIN_EMAIL` | 시트 열람자에게 계좌 비노출 |
| 0일 제출 | 허용(0원, 제출완료 처리, 메일에 "신청 없음" 문구) | 급식을 전혀 안 하는 직원 존재 가능 |
| 비고 | 200자 제한, 선두 `= + - @` 이스케이프(`'` 부착), 개인별내역 G열·로그에 반영 | 수식 주입 방지 |
| 재제출 | H:AL 31칸 전체 덮어쓰기(미선택=빈칸), 제출로그에 `수정` append | 중복 행 없음(§9) |
| 개인별내역 | 4행부터 스크립트가 전체 재생성(clear→setValues→합계행→병합·서식), E24 잔존 셀 삭제 | 직원 수 자동 대응 |

## 4. 시스템 아키텍처 및 데이터 흐름

### 4.1 데이터 흐름도


### 5.2 `학교급식` 시트 (기준 셀 1행, 헤더 2행, 데이터 3행~)

| 위치 | 내용 | 소유 |
|---|---|---|

## 7. 핵심 로직 설계

### 7.1 저장(`saveSubmission`) 처리 순서

1. 입력 정규화: `dateKeys` 중복 제거·정렬, `note` trim·200자 검증·`escapeCell`.
2. `ScriptLock.waitLock(30000)` 실패 → `LOCK_TIMEOUT`.
3. 배치 읽기(각 1회): 데이터 시트 전체, 학교급식!A1:F1, 설정 시트 가능일 표, 학교급식 AP열(직원ID 매칭).
4. 검증: 직원ID 존재·재직 → 년/월 일치(`MONTH_CHANGED`) → 각 dateKey가 해당 월 범위·실제 존재일 → 상태가 `불가`가 아님(`주의`는 허용) → 단가는 서버 값만 사용(클라이언트 전달 금액 무시).
5. 행 결정: AP열에서 직원ID 검색, 없으면 `syncEmployeesToMealSheet()` 후 재검색.
6. 쓰기(1회): `H:AP` 범위에 `[1|"" ×31, 제출일시, 비고, (메일상태는 이후), 직원ID]` `setValues`.
7. `rebuildPersonalStatement()`, 제출로그 `appendRow`(구분: AM이 비어 있었으면 `신규`, 아니면 `수정`).
8. `SpreadsheetApp.flush()` → 잠금 해제.
9. 메일 발송 시도 → 결과를 AO열에 기록(잠금 없이 단일 셀 `setValue`).
10. 응답 반환(금액은 `validDays × unitPrice`로 서버 자체 계산).

### 7.2 직원 동기화(`syncEmployeesToMealSheet`)

- 데이터 시트에서 성명이 비어 있지 않고 재직여부≠N인 행을 읽어, 학교급식 3행~에 **직원ID 기준으로 병합**합니다.
- 기존 행의 H:AO 데이터는 직원ID를 따라 이동(행 순서가 바뀌어도 신청 데이터 보존).
- 신규 직원 행에는 E/F/G 수식을 함께 기록합니다.
- 퇴직(N) 직원 행은 삭제하지 않고 유지(Q3 기본값), 드롭다운에서만 제외합니다.

### 7.3 월 생성(`generateMonth`) / 월 마감(`closeMonth`)

- **월 생성**: 입력 년/월의 말일 계산 → H2:AL2 숫자 값 기록(초과일 빈칸) → 설정 시트 가능일 표를 해당 월 날짜로 채움(토·일 `불가`, 나머지 `가능`) → 직원 동기화.
- **월 마감**: 확인 대화상자 → 학교급식 시트를 `학교급식_YYYY-MM`으로 복제(값 고정: `copyTo` 후 수식→값 변환) → 개인별내역도 `개인별내역_YYYY-MM` 복제 → H:AO 초기화 → B1/D1을 다음 월로 갱신 → 월 생성 실행 → 로그 기록.
- **`onEdit` 단순 트리거**: B1/D1/F1 편집 감지 시 "월 전환은 메뉴 '월 마감'을 사용하세요. 기존 신청자료가 남아 있습니다." 경고(값을 되돌리지는 않음).

### 7.4 날짜·타임존 규칙

- `appsscript.json` `timeZone: Asia/Seoul`.
- 서버는 `new Date(y, m-1, d)`로 요일을 계산하고 `Utilities.formatDate(..., "Asia/Seoul", "E")`로 라벨 생성. 클라이언트는 `new Date(문자열)`을 호출하지 않습니다.
- 제출일시는 문자열로 저장(시트 서식 의존 제거).

### Phase 0 — Preflight(사전 점검)

- **작업내용**: 워크북을 Google Sheets로 이관, `validateSheetStructure()` 초안 기준으로 시트명·헤더·기준 셀 존재 확인, `'이메일 '` 헤더 공백 제거, 개인별내역!E24 삭제, D1=10·F1=6850 갱신 여부 확인, Q1~Q5 답변 수집(미답 시 기본값 확정 기록), Script Properties 3개 키 입력 여부 확인.
- **완료조건**: 자기진단 함수가 경고 0건. 3장 답변(또는 기본값)이 본 문서 2장에 기록됨.
- **테스트방법**: 관리자 메뉴 "구조 점검" 실행 결과 확인.

### Phase 1 — Sheet 구조 정리

- **작업내용**: 데이터!E(직원ID)·F(재직여부) 추가, 학교급식!AM~AP 헤더 추가, 학교급식!A3:D 수식 제거(값으로 전환), H2:AL2 수식 제거, 설정·제출로그 시트 생성, 급식가능일 표 데이터유효성 설정, 시트 보호(설정·제출로그·개인별내역 담당자 전용).
- **완료조건**: 5장 구조와 100% 일치. 기존 테스트용 `1`값(H3:N16)은 마감 절차로 초기화.
- **테스트방법**: `validateSheetStructure()` 통과, 수식 오류(`#REF!`) 0건.

### Phase 2 — Backend(Config/Utils/Employee/Meal)

### Phase 3 — HTML UI

- **작업내용**: `Index/CSS/JavaScript.html` 작성(목업 레이아웃 준수: 제목·본인확인·급식일 그리드·전체체크/해제·실시간 계산·비고·저장·집계 카운트), viewport 메타, `withFailureHandler`, 30초 타임아웃, 버튼 중복 클릭 방지, `주의`일 기본 해제+경고.

## 11. 설치·배포·운영 가이드(초보자용 순서)

1. **Google Sheet 준비**: 워크북을 Google Sheets로 가져오기 → Phase 0·1 항목 적용(헤더 공백 제거, E24 삭제, 열 추가, 시트 추가).
2. **Apps Script 열기**: 확장 프로그램 → Apps Script.
3. **파일 생성**: 6장 목록대로 `.gs` 8개, `.html` 3개 생성, `appsscript.json` 표시 설정 후 timeZone 확인.
4. **코드 붙여넣기**: STEP 4 산출물 파일별 전체 붙여넣기.
5. **설정값 입력**: 설정 시트(학교명·은행명·입금기한·담당자메일), 프로젝트 설정 → Script Properties(`BANK_ACCOUNT`, `ACCOUNT_HOLDER`, `ADMIN_TOKEN`).
6. **권한 승인**: 관리자 메뉴 "구조 점검" 최초 실행 시 권한 승인(스프레드시트·메일 발송).
7. **초기화**: 메뉴 "직원ID 부여" → "월 생성(2026-10)" → 설정 시트에서 공휴일·예외일 편집 → "직원 동기화".
8. **테스트**: 메뉴 "테스트 메일(본인)" → 시크릿 창에서 제출 테스트 → T1~T30.
9. **Web App 배포**: 배포 → 새 배포 → 웹 앱 → 실행 계정 "나" → 액세스 권한(Q1 결과: 도메인 내 사용자 또는 모든 사용자) → URL 복사.
10. **직원 URL 안내**: Phase 8.5 통과 후 안내문 발송(메일/메신저). 관리자 상세표는 `URL?admin=<토큰>`으로 담당자만 사용.
11. **운영 중 년/월 변경**: 반드시 메뉴 **"월 마감"** 사용(D1 직접 편집 금지). 단가 변경은 F1 편집 후 "개인별내역 재생성", 이미 메일을 받은 직원에게는 별도 안내.
12. **장애 점검**: ① "구조 점검" 실행 ② 제출로그·AO열 메일상태 확인 ③ Apps Script 실행 로그(실행 기록) ④ 배포 버전 갱신 여부(코드 수정 후 "배포 관리 → 새 버전").

## 12. 에스컬레이션 규칙 및 Definition of Done

### 12.1 에스컬레이션 규칙(코딩 AI가 반드시 사용자 확인을 받아야 하는 경우)

- 3장 Q1~Q5의 기본값과 **다른 방향**으로 구현해야 할 근거가 발견된 경우.
- 시트 구조를 5장과 다르게 변경해야 하는 경우(열 추가·삭제·이동).
- 실제 메일 발송(테스트 메일 포함), Web App 배포, 시트 데이터 초기화(월 마감) 실행 전.
- 기존 워크북의 `1` 테스트 데이터를 삭제하기 전.
- Script Properties 값이 비어 있어 `{{...}}` 플레이스홀더가 메일에 남을 경우(발송 중단 후 보고).
- 6분 실행 제한·메일 quota 등 플랫폼 제약이 실제로 관측된 경우.

### 12.2 Definition of Done

- [ ] 5장 시트 구조와 실제 시트가 일치하고 `validateSheetStructure()` 경고 0건
- [ ] 6장 파일 11개 전부 생략 없이 작성되고 각 서버 함수가 `{ok, code, message, data}` 규약을 따름
- [ ] T1~T30 전 항목 PASS(결과표 첨부)
- [ ] 클라이언트에 이메일·계좌·토큰이 전달되지 않음(네트워크 응답 확인)
- [ ] 관리자 상세표가 토큰 없이 노출되지 않음
- [ ] 월 마감 실행 시 아카이브 시트가 값으로 고정되어 생성됨
- [ ] 메일 실패가 저장 실패로 이어지지 않음(T8·T25)
- [ ] 코드 내 하드코딩된 계좌·이메일·시트명 없음(`Config.gs` 상수·Script Properties만)
- [ ] 한국어 주석, 배치 I/O(저장 1회당 읽기 4회·쓰기 3회 이내), Asia/Seoul 고정
- [ ] Phase 8.5 인적 검토 체크리스트 4건 서명 완료
- [ ] 11장 설치·운영 가이드가 실제 절차와 일치함을 담당자가 확인
