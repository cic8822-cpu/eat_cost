[5. 년/월/날짜 동기화]
━━━━━━━━━━━━━━━━━━━━

이 부분은 매우 중요하다.

Google Sheet와 Web App이 반드시 동일한 년/월/날짜를 사용해야 한다.

Single Source of Truth 원칙을 적용한다.

기준값:

년도 = 학교급식!B1
월 = 학교급식!D1
급식단가 = 학교급식!F1

Apps Script는 이 값을 읽어서 Web App에 전달한다.

년도 또는 월이 변경되면:

1. 해당 월의 실제 마지막 날짜를 계산한다.
2. H2 이후에 1일부터 말일까지 생성한다.
3. 존재하지 않는 29/30/31일은 표시하지 않는다.
4. Web App 역시 동일한 날짜 목록을 보여준다.

예:
2026년 2월 → 1~28일
윤년 2월 → 1~29일
2026년 10월 → 1~31일

날짜 데이터는 단순 문자열 혼용으로 오류가 나지 않도록
내부적으로 YYYY-MM-DD 형태의 dateKey를 사용하라.

Web 화면에는
10/1(목)
10/2(금)
형태로 표시해도 된다.

[16. 보안 및 개인정보]
━━━━━━━━━━━━━━━━━━━━

웹앱에서 전체 직원 이메일 주소를 브라우저에 노출하지 않는다.

클라이언트로 전달할 직원정보는 최소화한다.

직원 선택 목록에는
employeeId, 직급, 표시용 성명 정도만 전달한다.

이메일은 서버에서 employeeId를 통해 조회한다.

Web App URL을 알고 있는 사람이 다른 사람 이름을 선택할 수 있다는 문제가 있으므로
1차 버전과 강화 버전을 구분하여 설계한다.

1차:
본인 선택 방식

강화:
Google Workspace 로그인 이메일과 직원 이메일을 비교하여 본인 자동확인

학교 Workspace 환경에서 Session.getActiveUser().getEmail() 사용 가능 여부와
Web App 배포 설정에 따른 제한도 설명한다.

━━━━━━━━━━━━━━━━━━━━
[17. 기존 파일 검토 시 반드시 확인할 사항]
━━━━━━━━━━━━━━━━━━━━

현재 자료에서는 다음 사항을 특별히 점검하라.

1. 년도/월 셀 위치 불일치
2. 일자 셀의 날짜 서식 문제
3. 기존 #NAME? 수식
4. 총일수 범위가 실제 31개 날짜 컬럼과 일치하는지
5. 직원 추가/삭제 시 고정 행 참조가 깨지는 문제
6. 개인별내역이 직원 수 증가에 자동 대응하는지
7. 이메일이 비어 있는 직원 처리
8. 년/월 변경 시 기존 신청자료가 유실될 위험
9. 직원 동명이인
10. 중복 제출
11. 동시에 여러 명이 저장할 때 충돌 가능성

문제를 발견하면 단순히 기존 구조를 복사하지 말고
Google Sheets + Apps Script에 적합한 방식으로 개선안을 제시하라.

━━━━━━━━━━━━━━━━━━━━
[18. PM-Agent 진행 방식]
━━━━━━━━━━━━━━━━━━━━

다음 5단계로 진행하라.

STEP 1 — 요구사항 및 기존 구조 분석
- 요구사항 정리
- 모순 또는 누락사항 탐지
- 구현 전 확인이 꼭 필요한 질문 제시
- 질문하지 않아도 합리적으로 결정 가능한 항목은 권장 기본값을 제안

STEP 2 — 시스템 설계
다이어그램 형태로 다음 데이터 흐름을 설명:

직원
↓
HTML Web App
↓
google.script.run
↓
Apps Script
↓
Google Sheets
↓
집계
↓
Email

그리고 각 Sheet와 Apps Script 파일의 역할을 정의한다.

STEP 3 — 구현계획
작업을 Phase 단위로 나눈다.

예:

Phase 1 Sheet 구조 정리
Phase 2 Apps Script Backend
Phase 3 HTML UI
Phase 4 저장/수정 로직
Phase 5 이메일
Phase 6 관리자 집계
Phase 7 테스트
Phase 8 배포

각 Phase에는:
- 작업내용
- 완료조건
- 테스트방법
을 작성한다.

STEP 4 — 전체 소스코드 생성
설계가 확정되면 복사/붙여넣기 가능한 완성 코드를
파일별로 제공한다.

코드 일부를 "...생략..." 형태로 생략하지 않는다.

STEP 5 — 설치/테스트/배포 가이드
초보자도 따라 할 수 있도록 다음 순서로 작성한다.

1. Google Sheet 준비
2. Apps Script 열기
3. 파일 생성
4. 코드 붙여넣기
5. 설정값 입력
6. 권한 승인
7. 테스트
8. Web App 배포
9. 직원 URL 안내
10. 운영 중 년/월 변경 방법

다음 원칙을 적용한다.

- 하드코딩 최소화
- 함수는 한 가지 역할에 집중
- 의미 있는 함수명 사용
- 한국어 주석 제공
- 에러 처리
- 서버 입력 검증
- 중복 코드 제거
- 배치 읽기/쓰기 사용
- getValue/setValue 반복 호출 최소화
- Range를 배열로 한 번에 처리
- LockService 적용
- 향후 직원 수 증가를 고려
- 시간대는 Asia/Seoul 기준
- 날짜 comparison 시 timezone 오류 방지
- 금액은 숫자로 저장하고 화면에서 원화 형식으로 표시
